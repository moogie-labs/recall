# Recall v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local-first Go TUI, CLI, and MCP application for folder-organized Markdown notes and tasks, with Neovim editing and offline hybrid search.

**Architecture:** Typed Markdown files are authoritative; a rebuildable SQLite index supports task queries and retrieval. The interfaces share Go application services, cooperating filesystem locks, and a lazily started per-collection embedding worker. Native runtime assets ship with Recall, while initialization downloads one pinned model.

**Tech Stack:** Go 1.27; Cobra; go-yaml v3; modernc SQLite; fsnotify; Bubble Tea v2/Lip Gloss v2; official MCP Go SDK; bundled llama.cpp; Nomic Embed Text v1.5 FP16.

**Spec:** `docs/superpowers/specs/2026-10-18-recall-design.md` — approved on 2026-10-18. Read both documents before execution.

**Execution status (2026-10-23):** Owner approved subagent-driven execution. All fourteen tasks are implemented, committed and individually reviewed. Whole-branch review and final independent verification are pending. The detailed step checkboxes below retain the original execution template; the completed task/commit map and implementation rulings are in `docs/implementation-decisions.md`, with actual acceptance results and limits in `docs/verification.md`.

## Global Constraints

- The application is named **Recall** and is implemented in **Go**.
- Storage is centralized on one computer. Running Recall inside another project must still use the same Recall collection.
- Folders are shared containers: each can contain subfolders, notes, and tasks.
- Note bodies remain free-form. There are no required note sections or templates.
- Automatic adoption is limited to files with compliant, type-bearing filenames.
- Initial task states are **Planned**, **In progress**, **Stalled**, and **Completed**.
- Tasks can be permanently deleted, including their history. There is no deleted state, trash folder, or application-level soft deletion.
- Only intermediate state history may be missed during direct edits; preserve the latest source content.
- SQLite is derived and rebuildable.
- The initial target machine is an M1 MacBook Pro with 16 GB RAM.
- Initial installation/downloads may require internet access. Normal indexing and searching run offline.
- Existing Ollama installations do not need to be detected or reused.
- Agents have full permissions within Recall, including noninteractive destructive operations.
- The initial task interface is a sortable/filterable list. Explicit document links/backlinks and Kanban columns are deferred.
- No generated answers, cloud sync, accounts, reminders, deadlines, tags, priorities, or dependencies in v1.

## Review Focus

1. Unicode, CRLF, delimiter-like Markdown, and unfamiliar YAML: preserve body bytes and unrelated fields; malformed metadata must not be overwritten — Tasks 1 and 3.
2. Traversal, symlinked paths, spaces, and long collection paths: operations stay confined to content, and runtime sockets still work — Tasks 2, 6, and 9.
3. Neovim-style atomic replacement, watcher overflow, and changing files during reconciliation: recover the latest contents without duplicate history — Tasks 3 and 7.
4. Stale agent reads, duplicate IDs, and deletion during embedding: reject conflicting writes and never resurrect removed documents — Tasks 5, 6, and 10.
5. Interrupted/tampered downloads or a failed native worker: initialization is retryable, source operations remain usable, and semantic failures are explicit — Tasks 8, 9, and 14.

### Collection, naming, and limits

- Root precedence: `--root` > absolute `RECALL_HOME` > `$HOME/.local/share/recall`. Resolve once, independently of cwd. Require explicit initialization; normal commands never create a new collection implicitly.
- Layout: `config.json`, `content/`, `index.sqlite`, `models/`, `runtime/`, and `run/` beneath the root. Runtime/model directories are not user folders.
- Managed filenames: nonempty `<name>.note.md` or `<name>.task.md`, with case-sensitive suffix matching. Do not infer type from content. An existing conflicting `type` is an error.
- Generate IDs from 16 cryptographically random bytes encoded as lowercase hex. Preserve existing nonempty IDs; detect duplicates without reassigning either file. IDs are never paths.
- Optional `title` defaults to basename without its full type suffix; do not require a Markdown heading. Preserve empty bodies and unknown metadata.
- Default editor argv is `["nvim"]`; allow an argv array in config. Never interpolate editor arguments through a shell.
- Task-list pagination defaults to 50, maximum 200, using an explicit nonnegative offset. Search defaults to 20, maximum 100. Add stable ID tie-breaking to every ordered query.
- Public human date inputs use local `YYYY-MM-DD` ranges: `from` includes that day; `through` includes its entire day. Convert to UTC `[From, Until)` using local calendar arithmetic, including DST. API timestamps are RFC3339 with a timezone.
- Query `Filter.Folder=""` means global regardless of `Recursive`; `"."` explicitly selects the content root. For a specified folder, `recursive=true` includes descendants and false matches direct children only. CLI folder filters default to recursive; the TUI folder browser uses nonrecursive listing. Tasks in the collection root are allowed.
- Reject symlinked content entries as unmanaged diagnostics; never follow them for discovery, reads, mutation, or recursive deletion. Reject `..`, absolute paths, and attempts to mutate the content root itself.
- Metadata coalescing: 250 ms quiet period; periodic full scan every 30 seconds in long-lived interfaces and after watcher errors. Scan on every process startup and explicit sync. One-shot writes may leave semantic work pending; they must not wait for model loading.

### Shared contracts

Introduce the following in `internal/model/types.go`; use the same types across packages. Names below are contractual; ordinary helper functions remain implementer decisions.

```go
type Kind string
const ( Note Kind = "note"; Task Kind = "task" )
type State string
const (
    Planned State = "planned"
    InProgress State = "in_progress"
    Stalled State = "stalled"
    Completed State = "completed"
)
type Event struct { State State; At time.Time }
type Ref struct { ID string; Path string } // exactly one supplied
type Document struct {
    ID, Path, Title string
    Kind Kind
    State State
    History []Event
    Body, Raw, Revision string // revision is SHA-256 of raw source bytes
}
type Diagnostic struct { Code, Path, Message string }
type Snapshot struct { Documents []Document; Diagnostics []Diagnostic; Folders []string }
type DateField string // "created", "state_changed", "transition"
type Filter struct {
    Folder string; Recursive bool
    Kinds []Kind; States []State
    DateField DateField; EventState State
    From, Until *time.Time
}
type TaskQuery struct { Filter Filter; Sort string; Desc bool; Limit, Offset int }
type Page[T any] struct { Items []T; NextOffset *int }
type SearchQuery struct { Filter Filter; Text, Mode string; Limit int }
type Hit struct {
    ID, Path, Title, Snippet, IndexState, Revision string
    Kind Kind; State State
    StartLine, EndLine int; Score float64
}
type SyncReport struct { Added, Updated, Removed int; Diagnostics []Diagnostic }
type Error struct { Code, Message, Path string }
```

Implement `(*model.Error).Error() string` and `model.ErrorCode(error) string`. Stable codes: `not_initialized`, `invalid_argument`, `invalid_document`, `type_mismatch`, `duplicate_id`, `not_found`, `already_exists`, `conflict`, `outside_root`, `folder_not_empty`, `index_unavailable`, `indexing`, `runtime_unavailable`, `asset_invalid`, and `unsupported_platform`. Plain unexpected errors map to `internal`; do not expose raw document content in errors/logs.

Use `func() time.Time` and `func() string` injection for deterministic clocks/IDs. Request-scoped I/O takes `context.Context`; synchronous resource constructors and configuration discovery are exceptions. `Ref` resolution must not choose silently when ID/path is ambiguous. Public DTOs use explicit lower_snake_case JSON tags (`ID` becomes `id`, `NextOffset` becomes `next_offset`); Go snippets omit imports, not required assertions.
